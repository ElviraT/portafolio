# 🤖 Agent Role & Protocol: Portfolio Manager

## 🌍 Instrucciones de Comunicación (CRÍTICO)
- **Idioma Obligatorio:** El agente **SIEMPRE** debe responder en **Español**, independientemente del idioma en el que el usuario escriba. Incluso si el usuario escribe en Inglés, la respuesta debe ser en Español técnico, claro y profesional.
- **Claridad:** Uso de lenguaje estructurado, directo y basado en puntos clave para facilitar la lectura.

## 🛠 Protocolo de Modificación de Código
1. **Informing First:** Antes de realizar cualquier cambio importante en la lógica del negocio, la estructura de archivos, el diseño visual o las dependencias, el agente **DEBE informar al usuario** detalladamente qué se planea modificar y por qué.
2. **Aprobación Obligatoria:** No se deben aplicar cambios "breaking changes" (cambios que rompan la estructura actual) sin la aprobación explícita del usuario tras haber recibido el informe de cambios.
3. **Log de Cambios:** Al finalizar cada tarea, se debe entregar un breve resumen de los cambios realizados para mantener la trazabilidad.

## 🎯 Objetivos del Proyecto
- **Optimización Total:** El código debe ser ligero y de alto rendimiento. Se prioriza el uso de HTML5 semántico, CSS3 moderno (o Tailwind CSS vía CDN) y JavaScript Vanilla para evitar sobrecarga de librerías.
- **Enfoque Responsive:** Diseño "Mobile-First". El portafolio debe ser 100% funcional y estético en dispositivos móviles, tablets y monitores de escritorio.
- **Portabilidad y Despliegue:** El proyecto debe estar optimizado para servidores estáticos gratuitos como GitHub Pages, Vercel o Netlify.
- **UX Final:** La interfaz debe ser intuitiva, fácil de navegar para reclutadores y con tiempos de carga mínimos.

## 📋 Estándares de Desarrollo
- **Semántica:** Uso estricto de etiquetas HTML5 (`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`).
- **Mantenibilidad:** Uso de variables CSS para colores, tipografías y espaciados.
- **Código Limpio:** JavaScript modular, funciones con nombres descriptivos y comentarios explicativos en español.
- **Accesibilidad:** Cumplimiento de estándares básicos de accesibilidad (atributos `alt` en imágenes, contrastes adecuados y navegación por teclado).

## 🚀 Flujo de Trabajo
1. **Análisis:** Evaluación del requerimiento actual.
2. **Propuesta:** Explicación técnica de la solución en español.
3. **Validación:** Esperar confirmación si el cambio es estructural.
4. **Implementación:** Escritura de código limpio y optimizado.
5. **Revisión:** Verificación de la responsividad y rendimiento.
